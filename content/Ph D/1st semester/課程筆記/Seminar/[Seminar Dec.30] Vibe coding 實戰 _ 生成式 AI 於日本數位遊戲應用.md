講者於日本遊戲產業工作
整場演講主要介紹以自身產業經歷，對於vibe coding 的實際情況以及初步的介紹大型語言模型的使用的一些特色與心得

以下分成幾段說明
### 日本遊戲產業
根據講者的經驗，由於日本企業文化的關係，在推動整合AI 到原有的工作流程，速度相對較慢。
由於日本對於資料安全以及著作權法的觀念較為嚴格，民族性較難接受新的技術工具，因此，目前講者所接觸的幾間大型的日本遊戲開發商，並未導入 Vibe coding 於實際工作場域的應用。

### Vibe coding 
Vibe coding ，引用自Andrej Karpathy 的發言。"有一種軟體開發方法，強調開發者只需使用自然語言向ai描述需求，而無須理解底層程式碼的運作方式"，讓使用者順應氛圍、忘記程式碼的存在。
整個流程轉變為**描述需求** $\rightarrow$ **評估結果** $\rightarrow$ **提供回饋**

若將製作遊戲分成三大區塊，美術(Artist)、企劃(Game design)、程式(Engineer)。ai 近幾年的崛起，對於衝擊較大的預期的改變有以下幾點
1. 對於擁有一方技能的人員，可藉由ai 的協助做槓桿
可以加速完成或是補足自身的能力的不足。未來可能會有越來越多的小型獨立遊戲開發單位的出現。
2. 對於工程角度而言，藉由ai的輔助會加速資深的工程師的工作進程，而對於入門的工程師而言，也可以藉由ai的協助快速的做出較為初階的成果，降低入門的難度。

講者過去在vibe coding 的經驗來自於自己私下的研究，直到今年換工作後，才開始於職場與ai 協作進行編程。
講者在與ai 協作過程中的幾點擔憂，例如: 
1. 程式的長期維護性
使用者若直接採用ai 生成的程式碼，但不對內容作通盤的理解，未來進行修改甚至維修時，都會付出相對應的代價。

2. ai 幻覺(Hallucination)
目前生成式ai 所生成的內容並不能保證100%正確，因此還是需要有軟體工程師，進行審核、修改與測試。

3. 阻礙初階工程師的成長
擁抱新的工具並非壞事，但若過於依賴工具，則有礙於自身能力的培養。由於工程師未來還是需要獨立去判斷、評估程式碼的優略，因此必備的能力並不能依托於工具之上。

### 建議
講者對於使用LLM進行coding 提出幾個相關的建議
1. 減少雜訊
2. context window區分

對於學生的學習程式的建議，雖然目前直接使用ai 或是利用ai輔助編寫程式相當方便且快速，但對於初步入門的工程師基礎的編程功能還是不可或缺，由於ai 使用者為所生成程式的第一審核者，因此就必須具備一定的能力對於內容有所理解與評斷。
